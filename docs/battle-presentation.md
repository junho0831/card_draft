# 전투 화면 우선 리디자인

2026-09-13. 전체 UI 리디자인의 첫 검증 화면은 전투다. 우선 기준 해상도는 데스크톱 1280×720, 모바일 390×844다. 다른 화면의 전면 재구성까지 완료한 것으로 표시하지 않는다.

## 구현

- 전장과 손패를 감싸던 큰 테두리를 제거하고 배경 위에 카드를 직접 배치한다.
- 데스크톱 영웅은 전장 왼쪽에 유지하되 폭을 300→248로 줄인다. 전장 슬롯은 128×132→154×140, 손패는 174×182→194×204로 확대한다.
- 손패 제목용 왼쪽 240px 영역을 제거하고 카드를 중앙 정렬한다. 그림 높이는 48→96px, 공격·체력은 그림 하단 모서리에 표시한다.
- 모바일 전장 슬롯은 100×90→112×112, 손패는 164×202다. 손패 그림 높이는 54→96px다. 가로 스크롤을 유지한다.
- 상단에는 현재 행동 안내 한 줄만 남긴다. 도전 진행·상세 도움·덱·로그는 정보 창에서 열고 닫는다. 정보 창 안에서도 기존 안내 확인 동작을 제공한다.
- 취소는 고정 하단 행동 버튼에서 한다. 대상 선택 중 아군 테두리와 짧은 배지를 강조하고, 손패와 적 유닛은 어둡게 표시한다. 중복되는 큰 대상 선택 문구는 제거했다.
- 데스크톱 카드 호버 확대는 1.1배로 줄였다. 모바일 이동 폭도 줄여 조작 중 카드가 크게 뛰지 않게 했다.
- `src/ui/components/battle_presentation.gd`에 크기·배경·정보 창 배치를 분리했다. 전투 계산과 저장 규칙은 이 컴포넌트에 넣지 않는다.

## 검증 방법

`capture_battle_redesign.gd`는 테스트 전장을 구성한 뒤 실제 GUI 입력을 주입한다. 정보 열기·닫기, 장비 선택, 모바일 두 번 누르기, 하단 취소를 검사한다. 정보 확인과 취소에서 마나·체력·손패가 변하지 않는지도 확인한다. 각 실행은 반드시 별도 저장 경로를 사용한다.

```bash
xvfb-run -a godot --path . -s res://tests/godot/capture_battle_redesign.gd -- --test-data-dir=/tmp/card-draft-battle-desktop
xvfb-run -a godot --path . -s res://tests/godot/capture_battle_redesign.gd -- --test-data-dir=/tmp/card-draft-battle-mobile --mobile
godot --headless --path . -s res://tests/godot/run_tests.gd -- --test-data-dir=/tmp/card-draft-battle-regression
```

각 저장 폴더에 `battle.png`, `targeting.png`, `information.png`를 생성한다. 캡처의 마나 4와 전장 유닛은 비교를 위한 fixture이며 실제 시작 수치는 바꾸지 않는다.

## 검증 범위 구분

- 구현 확인: 위 두 기준 크기에서 전투·대상 선택·정보 창을 렌더링하고 실제 입력으로 검사한다.
- 자동 검사: 세 세력의 첫 플레이 입력과 전체 회귀 검사 결과는 실행 로그로 구분한다.
- 아직 미측정: 신규 사용자 이해도, 재미, 10~15분 완주, 실제 저사양 모바일 브라우저 성능.
- 기존 종료 시 CanvasItem/ObjectDB 해제 경고는 별도 문제로 남아 있다.

다음 화면에 적용할 기준은 큰 카드 원화, 하나의 주요 행동, 설명의 별도 정보 창, 고정된 모바일 조작부다. 지도 미래 지점은 숨기지 않고 읽을 수 있게 유지하며, 모바일은 각 화면 작업과 함께 검증한다.
