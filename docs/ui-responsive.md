# Card Draft 반응형 UI

이 문서는 PC, 웹, 태블릿, 모바일에서 유지해야 할 UI 계약만 기록한다.

## 기준

기본 viewport는 `1280×720`, stretch mode는 `canvas_items`다. 현재 루트는 물리 화면 크기를 가로 캔버스로 정규화하고 안전 영역을 반영한다. 세로 크기 입력 테스트를 독립된 세로 레이아웃 지원의 증거로 해석하지 않는다.

- 데스크톱 자동 배율 기준 상한 `MAX_AUTO_UI_SCALE`은 1.45다.
- UI 크기 배수는 자동 1.0, 크게 1.1, 작게 0.9다. 비터치 경로의 최종 clamp 범위는 0.95~1.566이다. 따라서 수동 보정까지 포함한 절대 상한을 1.45라고 쓰지 않는다.
- 작은 비터치 화면에서 native scale이 1 미만이면 1을 반환한다.
- 터치 배율은 `max(1, 짧은 물리 변 / 390) × UI 크기 배수`다. 데스크톱 상한을 터치 경로에 적용하지 않는다.
- 설정 화면에는 큰 화면용으로 안내되어 있지만, 현재 배율 계산 자체에 1280px 이상으로 한정하는 조건은 없다.

기준 검증 크기는 1920×1080, 1280×720, 1024×768, 844×390, 667×375이며 800×1280·390×844 입력에서도 가로 정규화와 잘림 여부를 확인한다. 배율의 기준 구현은 `src/ui/layout_policy.gd`와 `src/core/main.gd`다.

## 재배치

- 창 크기와 방향 변경은 0.2초 디바운스 후 현재 화면을 다시 만든다.
- 주요 폭 기준은 `600`, `860`, `900`, `1080`, `1400`, 높이 기준은 `760`이다.
- 전투는 손패, 필드, 턴, 로그를 유지하고 표시 노드만 재생성한다.
- 전투 입력이 잠긴 동안에는 재배치를 미룬다.
- 작은 화면의 긴 목록·설명은 스크롤하고 손패는 가로로 넘긴다. 현재 가로 전투의 두 전열은 한 화면에 고정한다.

## 레이아웃

- 루트는 `ScrollContainer` 안의 `VBoxContainer`를 기본으로 한다.
- 공통 셸은 `UiFactory.begin_screen()`과 `make_screen_panel()` 또는 `make_scroll_panel()`을 사용한다.
- 화면별 고정 폭 계산을 추가하지 않는다.
- 넓은 화면의 2열은 860px 아래에서 1열로 바꾼다.
- 버튼은 [공통 버튼 규격](button-system.md)을 따른다.
- 전장·손패·행동 영역은 화면 크기에 맞춰 계산한다. 가로 전투는 적·아군 두 전열과 영웅을 함께 표시하고, 손패의 넘치는 카드는 가로 스크롤로 접근한다. 카드 상세의 긴 설명은 별도로 스크롤한다.

관련 구현:

```text
src/core/main.gd
src/ui/ui_factory.gd
src/ui/components/card_view.gd
src/ui/styles/ui_tokens.gd
src/ui/styles/ui_styles.gd
src/ui/styles/battle_styles.gd
src/ui/screens/*.gd
```

## 카드와 버튼

카드 정보 순서:

```text
비용/이름 -> 아트 -> 타입/세력 -> 핵심 효과
```

- `CardView` 모드는 `hand`, `field`, `reward`, `shop`, `collection`만 사용한다.
- 세력·공용 스킨은 구조가 아니라 프레임과 이름 띠에 적용한다.
- 상태색 우선순위는 `타겟/선택 -> 추천 -> 사용 가능 -> 세력색`이다.
- 버튼 역할은 `primary`, `secondary`, `danger`, `power`로 통일한다.
- 버튼 안에 긴 설명을 넣지 않는다.
- 손패는 `_hand_slot`을 유지하며 카드를 사용해도 남은 카드가 갑자기 이동하지 않아야 한다.
- 현재 가로 전투의 탭·길게 누르기·취소 규칙은 [모바일 조작](mobile-controls.md)을 따른다.
- 가로 모바일 손패 카드의 논리 크기는 `96×144`다. 손패 영역은 평소 `116`, 대상 선택 중 `72` 높이로 접히며, 카드 자체를 납작하게 줄이지 않는다. 평소에는 비용·이름, 대상 선택 중에는 비용과 터치할 영역을 유지한다.
- 모바일 카드 탭은 전체 카드 상세를 열고, 상세의 `사용`으로 진행한다. 데스크톱 손패는 `132×198`로 전체를 표시하며 클릭으로 사용한다. 위 수치는 배율 적용 전 논리 크기다.

## 화면별 필수 조건

- 메인 메뉴: 주 행동이 첫 화면에 보이고 860px 아래에서는 1열이다.
- 세력 선택: 카드 전체가 클릭 대상이며 모바일 시작 버튼은 쉽게 닿아야 한다.
- 맵: 현재 진입 가능한 노드와 현재 빌드가 먼저 보인다.
- 전투: 목표, 적/내 필드, 손패, 필살기, 턴 종료에 접근할 수 있어야 한다.
- 보상: 후보 카드와 선택 이유를 확인하고 확정 버튼에 접근할 수 있어야 한다. 모바일 상세 창에서도 수령할 카드를 명확히 표시한다.
- 상점: 가격과 구매 가능 상태가 카드 설명보다 먼저 구분돼야 한다.
- 이벤트·휴식: 선택의 비용과 결과가 버튼 밖 설명으로 보인다.
- 결과: 승패, 최종 빌드, 획득 보상, 새 런 행동을 제공한다.

1280×720에서는 전장과 핵심 행동 버튼이 첫 화면에 남아야 한다. 800×1280과 390×844 입력도 가로 캔버스로 정규화한 뒤 전장·손패·행동 영역이 겹치지 않는지 확인한다. 긴 목록의 세로 스크롤과 손패의 가로 스크롤을 전장 세로 스크롤로 혼동하지 않는다.

## 검증

기본 회귀:

```bash
godot --headless --path . -s res://tests/godot/run_tests.gd -- --test-data-dir=/tmp/card-draft-ui-regression
```

UI 변경 시:

```bash
godot --path . -s res://tests/godot/capture_ui_responsive.gd -- --test-data-dir=/tmp/card-draft-ui-captures
godot --path . -s res://tests/godot/validate_ui_captures.gd -- --test-data-dir=/tmp/card-draft-ui-captures
```

캡처 스크립트는 화면 이름과 `active_screen` 일치를 확인하고 draw 완료 후 PNG를 저장한다. 검은 이미지, 10KB 이하 파일, 이전 화면 잔상은 실패다.

수동 체크:

- 버튼과 라벨이 잘리거나 한 글자씩 줄바꿈되지 않는다.
- 손패 사용 전후 남은 카드 슬롯이 유지된다.
- hover 확대가 다른 카드나 행동 버튼을 가리지 않는다.
- 공용 카드의 `공용 · 모든 세력` 문구가 잘리지 않는다.
- 세로 크기 입력을 가로 캔버스로 정규화해도 두 전열과 행동 버튼이 보이며, 마지막 손패까지 넘겨 상세 확인·사용할 수 있다.
