# 화면 실행 검증 — 2026-09-15

대상은 `02c4f52` 이후 중복 검사 정리가 적용된 작업 트리다. 게임 구현은 해당 커밋과 동일하며, Android QA 사본의 `src` 차이는 테스트 저장 경로 주입뿐임을 확인했다. 기존 x86_64 QA APK를 다시 설치했다. ARM64 출시 빌드를 새로 검증한 결과는 아니다.

## 가속과 저장 분리

에뮬레이터를 화면이 보이는 상태에서 `-accel on -cores 2 -memory 2048 -gpu host -no-snapshot-load -no-snapshot-save -no-boot-anim`으로 실행했다. 실행 중인 QEMU PID 1355759의 파일 디스크립터에서 `/dev/kvm`, `anon_inode:kvm-vm`, `anon_inode:kvm-vcpu:0`, `anon_inode:kvm-vcpu:1`을 확인했다. 이번 실행은 VT-x/KVM 실제 사용을 확인한 실행이다. 이전 실행의 가속 사용을 소급해서 증명하지는 않는다.

Android 게임 로그의 GL 장치는 Intel UHD Graphics의 Emulator OpenGL ES Translator였다. 시작 로그에 GPU 사용 불가 메시지가 있었으나 이후 Intel 장치로 실제 렌더링한 로그를 확인했다. 셰이더 캐시 재컴파일 경고도 있었다.

화면은 ADB로 1280×720, density 160으로 설정했다. API 36 AVD는 `pocket_portal_api36`, 앱은 `com.card_draft.mobileqa`다. QA 앱 데이터만 초기화했으며 저장 로그는 `/data/user/0/com.card_draft.mobileqa/files/mobile-qa-0914`를 가리킨다. PC 검사는 `/tmp/full-visible-0915/` 아래 별도 저장 경로를 사용했다.

## 발견한 문제와 한계

- Android 1280×720에서는 지도 진행 버튼에 도달하기까지 여러 번 스크롤해야 했다. 정보 패널이 진행 행동보다 앞서 긴 공간을 차지한다.
- 전투의 아군 선택 시 적 영웅이 위로 가려진 상태가 유지됐다. 전장 중앙을 아래로 스와이프해 적 영웅을 표시한 뒤 공격은 가능했다. 공격 대상 안내·자동 이동 사용성의 추가 개선 대상이다.
- 전체 회귀 종료 시 기존 CanvasItem 23개와 ObjectDB 정리 경고가 남아 있다. 기능 테스트 통과와 구분한다.
- Android 앱 재개 후 메모리 단일 스냅샷은 PSS 231,418KB, RSS 360,276KB였다. 최대값·실물 폰 측정·장기 누수 검증이 아니다.
- 에뮬레이터 부팅 뒤 프로세스의 누적 평균 CPU 표시값은 89.3%였다(경과 1분 9초 시점, PC 검사와 동시 실행 포함). PC 전체 CPU 사용률이나 안정 상태 게임 부하로 해석하지 않는다. CPU 감소율·실기기 FPS·발열은 측정하지 않았다.

로컬 캡처 29장과 로그: `build/visible-test-2026-09-15/index.html`. Android 캡처와 PC 캡처를 폴더로 구분한다. 가속 증거는 같은 폴더의 `kvm-proof.txt`에 남겼다. 에뮬레이터 화면은 이어하기한 전투 상태로 열어 두었다.

## 발견 문제 수정

- 좁은 가로 지도에도 진행 버튼을 하단에 고정했다. 경로·목표를 범례보다 먼저 배치하고, 가로 고정 버튼의 반복 보상 설명을 생략했다. 경로 선택과 기존 지도 데이터는 유지한다.
- 공격 가능한 아군을 선택하면 선봉이 있을 때 선봉을, 없을 때 영웅을 표시한다. Android 터치 해제가 끝난 다음 프레임에 기존 이동 로직을 사용하며 선택만으로 공격하지 않는다. 사용자의 새 스크롤에 의한 이동 취소는 유지한다.
- 손패가 비어 있을 때 이전 손패 영역 높이가 전장을 압박하던 문제도 수정했다.
- `visible_navigation_test.gd`에서 640×360 가로 화면의 고정 버튼, 스크롤 중 위치 보존, 선봉/영웅 표시, 빈 손패, 선택 전후 전투 상태 보존을 확인했다. 최종 검사 로그는 `/tmp/fix-visible-nav-final.log`이며 통과했다.
- 전체 회귀 2,325개 통과(`/tmp/fix-visible-regression-clean.log`), 기존 리소스 정리 경고는 남는다. 이후 가로 지도 버튼 설명 축소는 위 화면 검사로 재확인했다.
- Android 1280×720 수정 APK에서 첫 지도 화면의 진행 버튼 노출과 아군 선택 후 적 영웅 자동 표시를 ADB 입력으로 확인했다. 수정 전처럼 대상 표시를 위해 별도로 전장을 스와이프할 필요가 없어졌다. 실물 폰 검증은 아니다.

## 종료 시 노드 누수 수정 — 2026-09-16

전투 UI의 `enemy_row`가 모든 배치에서 생성되지만 `wide_tight` 배치에서만 트리에 붙는 것이 원인이었다. 다른 배치에서는 이 빈 HBoxContainer가 해제되지 않았다. 해당 배치에서만 생성하도록 바꿨다.

수정 후 Godot 4.6.3 전체 회귀 2,325개 통과. 상세 로그 `/tmp/leak-fixed-0916.log`에서 기존 CanvasItem 23개·ObjectDB 누수 경고와 `Leaked instance` 출력이 사라졌다. `visible_navigation_test.gd`에는 화면 재구성·종료 전후 orphan node 수가 증가하지 않는 검사를 추가했고 표시 창 실행에서도 통과했다(`/tmp/leak-navigation-0916.log`).

`--verbose` 종료 출력에는 `process_frame`의 `Orphan StringName` 진단이 남아 있다. 모든 엔진 리소스의 누수가 없다고 단정하지 않는다. 이번 수정은 Godot PC 전체 검사와 표시 창 검사로 검증했으며 Android APK는 이 변경으로 다시 빌드하지 않았다.

## 에뮬레이터 화면 비율 보정 — 2026-09-16

위 Android 검증의 1280×720 설정은 원래 AVD(1080×2340)의 비율을 유지하지 않았다. 이후 크기를 720×1560, density를 293으로 바꾸고 가로 회전을 적용해 1560×720 화면으로 확인했다. 에뮬레이터 설정 변경이며 게임 코드나 배포 설정 변경은 아니다. 이 비율에서도 전장 스크롤 위치에 따라 적 영역이 위로 가려지는 현상이 남아 있어, 자동 대상 이동 통과와 전체 전장 동시 표시를 구분한다.
