# 모바일 조작 기준

모바일에서는 터치 조작과 좁은 화면의 가독성을 우선한다. 전투 수치와 카드 효과는 변경하지 않는다.

- 스크롤 영역의 카드·버튼 위에서도 밀어서 이동한다. 가로 손패와 세로 화면은 이동 방향으로 구분하고, 스크롤 후 손을 떼어도 카드를 사용하지 않는다.
- 세로 모바일 카드는 한 번 눌러 확인하고 다시 눌러 사용한다. 가로 모바일은 카드 상세 창의 사용 버튼으로 확정한다. 장비·희생 대상은 직접 고르며 취소할 수 있다. 데스크톱 마우스 드래그는 유지한다.
- 세로 전투의 주 행동·필살기·취소/턴 종료는 하단에 고정한다. 가로 전투는 도움·필살기·취소/턴 종료를 오른쪽에 고정한다. 전장과 손패는 별도 스크롤 영역에 두어 고정 버튼 뒤로 숨지 않게 한다.
- 상점·보상·세력 선택의 공통 하단 메뉴도 콘텐츠와 별도 영역을 사용한다.
- 전투 하단·공통 동작 버튼은 모바일에서 최소 56px 높이를 사용한다. 전투 주 행동·턴 종료 글씨는 18px, 필살기와 상단 정보·메뉴는 16px이다. 상단 정보·메뉴는 높이 48px를 확보한다. 긴 필살기 이름은 두 줄로 표시한다. 실제 손가락 크기는 화면 배율과 기기에 따라 다르므로 기기 확인이 필요하다.
- 상태·전투 상세 정보는 상단 정보 버튼으로 연다. 모바일에서 같은 기능의 상세 버튼과 불필요한 빈 공간을 줄인다.
- 작은 화면에서는 세로 스크롤을 허용한다. 읽을 수 없을 정도로 카드를 축소해 한 화면에 강제로 넣지 않는다.

## 행동 가능 상태와 공격 예측

- 사용 가능한 손패에는 초록색(추천 카드는 금색) 발광 테두리를 표시한다. 마나·필드·대상 조건을 충족하지 못하거나 상대 턴이면 어둡게 표시한다. 어두운 카드도 설명 확인은 가능하다.
- 모바일은 기존 두 번 누르기 사용 방식과 대상 선택·취소를 유지한다. 공격자를 선택하면 유효한 적에 붉은 테두리와 `적 HP 현재 → 예상 / 내 HP 현재 → 예상`을 표시한다. 데스크톱에서는 대상 위에 포인터를 올릴 때 연결선, 카드 드래그 시 화살표를 표시한다.
- 체력 예측은 타격·반격 직후 기준이다. 처치 시 반격 없음과 돌파는 기존 계산을 공유하며, 후속 사망·장비 효과 전체를 시뮬레이션한 최종 체력은 아니다.
- 턴 버튼은 `내 턴 · 턴 종료`(금색), 가능한 카드·공격·필살기가 모두 없을 때 `턴 종료`(초록색), `행동 처리 중`, `상대 턴`(비활성), `선택 취소`로 바뀐다. 내 턴에는 행동이 남아 있어도 턴을 종료할 수 있다. 카드 사용·공격 순서를 제한하는 별도 단계는 추가하지 않는다.
- 테두리와 색 외에도 비활성 이유·체력 숫자·버튼 문구로 상태를 구분한다. 지속 점멸 대신 고정 발광을 사용한다.

자동 검증: `capture_battle_redesign.gd`를 390×844(`--mobile`)와 1280×720에서 실행해 대상 선택·취소, 비활성 카드, 턴 상태, 처치/비처치 체력 예측과 예측 중 상태 보존을 확인했다. 기존 회귀 검사 1,345개도 통과했다. 화면 자료는 `build/active-state-2026-09-14/`에 보관한다. 사람이 이 표시를 보고 더 쉽게 이해하는지는 별도 플레이 관찰이 필요하다.

추가 검증에서는 실제 클릭 공격 후 처치 여부와 양쪽 체력이 예측과 일치하는지 확인했다. 데스크톱 대상 호버 시 화살표 표시 및 공격 후 제거도 확인했다. 발광은 카드 중앙을 칠하지 않도록 수정했으며, 전투 화면 종료 후 대기 중이던 손패 갱신이 제거된 화면에 접근하는 오류를 방지했다. `mobile-attack-polished.png`와 `desktop-attack-arrow.png`가 수정 후 자료다.

대상 선택 취소 또는 공격자 선택 시 이전 손패 미리보기도 해제한다. 장비의 ‘아군 선택’ 안내가 공격 대상·체력 예측과 겹치지 않도록 했다.

Android 에뮬레이터에서도 저장된 장비 학습 전투를 재개해 적을 직접 눌렀다. 표시된 `적 HP 1→0 / 내 유닛 HP 2→2`와 실제 결과가 일치했고, 돌파 피해 2로 적 영웅 HP는 11→9가 됐다. 자료는 `android-preview-polished.png`, `android-after-attack.png`다. 실제 사용자 저장과 분리된 QA 앱에서 실행했다.

## 검증

모든 실행은 `--test-data-dir`로 실제 저장과 분리한다.

```bash
xvfb-run -a godot --path . -s res://tests/godot/touch_scroll_test.gd -- --test-data-dir=/tmp/card-draft-mobile-390
xvfb-run -a godot --path . -s res://tests/godot/touch_scroll_test.gd -- --test-data-dir=/tmp/card-draft-mobile-320 --small-phone
godot --headless --path . -s res://tests/godot/run_tests.gd -- --test-data-dir=/tmp/card-draft-mobile-regression
```

입력 검사는 스크롤 중 상태 보존, 중복 이벤트, 버튼 크기, 하단 고정 위치와 콘텐츠 영역 분리를 확인한다. 화면 크기 검사는 실기기의 성능·발열·안전 영역·브라우저 주소창 변화 검증을 대신하지 않는다. 실제 Android/iPhone에서 한 손 조작과 1회 전투 완료를 별도로 확인해야 한다.

2026-09-13: Godot 4.6.3 회귀 검사 1,343개 통과. 390×844 주요 화면 9종과 전투 대상/손패 추가 캡처 완료. 320×568·390×844 전투 입력 검사에서 하단 고정·영역 분리·스크롤·전투 상태 보존 확인. 기존 종료 시 리소스 경고는 남아 있으며, 실기기 검증은 미실시다.

### 2026-09-14 Android 에뮬레이터 검증

Android API 36 에뮬레이터(1080×2340, density 440)에서 ADB 터치·스와이프로 직접 플레이했다. 테스트 전용 패키지 `com.card_draft.mobileqa`와 저장 경로 `/data/user/0/com.card_draft.mobileqa/files/mobile-qa-0914`를 사용했다. 실행 시 `--test-data-dir`를 전달했고 QA 빌드의 기본 저장 경로도 같은 위치로 고정했다. 사용자 앱의 저장은 사용하지 않았다.

- 세력 선택·지도 중앙에서 스와이프하고, 스와이프 직후 한 번의 터치로 다음 화면에 진입했다.
- 카드 확인 후 재터치 소환, 아군 선택 후 영웅 공격, 턴 종료를 직접 조작해 인간 첫 학습 전투에서 승리했다.
- 손패 가로 스와이프는 카드·마나를 소비하지 않았고, 전장을 덮는 마우스 호버 미리보기도 나타나지 않았다.
- 앱 재시작·QA APK 업데이트 후 전장과 진행 상태가 유지됐다.
- 장비 학습에서 대상 선택·취소 시 마나 2와 훈련용 검이 유지됐다. 다시 선택해 아군에 장착한 뒤 마나 0, 카드 소비, 아군 공격력 1→3을 확인했다.

실행 중 발견한 Android 가로 시작 설정, 고해상도 휴대폰의 화면 배율, 터치 후 마우스 호버 표시, 스와이프 다음 첫 터치 누락을 수정했다. 세로 휴대폰은 논리 너비 390 기준으로 배율을 적용한다. 회귀 검사 **1,345개 통과**, 터치 입력 검사도 통과했다. 기존 종료 시 리소스 경고는 남아 있다.

캡처는 `build/mobile-android-qa-2026-09-14/`에 있다. `17-swipe-fixed.png`, `19-victory.png`, `21-post-swipe-tap.png`, `24-target-selection.png`, `25-cancelled.png`, `26-equipped.png`가 주요 확인 자료다. 에뮬레이터 검증이며 실물 Android/iPhone, 오디오 청취 품질, 장시간 성능·발열, 신규 사용자 완료 시간은 검증하지 않았다. 테스트용 x86_64 APK는 휴대폰 배포용 빌드가 아니다.

### 버튼 가독성 수정 (2026-09-14)

버튼 글씨·높이만 조정했다. 390×844와 320×568 터치 스크롤 검사, 390×844 및 1280×720 전투 입력 검사가 통과했다. Android 에뮬레이터의 별도 QA 앱에서 이어하기와 정보 열기·복귀를 직접 입력하고 메뉴·전투·정보 화면을 확인했다. 캡처는 `build/button-readability-2026-09-14/`에 있다. GUI 검사 종료 시 기존 CanvasItem/ObjectDB 해제 경고는 남아 있다. 실물 휴대폰에서의 가독성 평가는 별도로 필요하다.

### 가로모드 버튼 1차 수정 기록 (아래 재배치로 대체)

휴대폰 회전을 허용하며, 가로·세로 모두 짧은 변을 기준으로 동일한 터치 배율을 사용한다. 가로 화면에서는 주 행동·필살기·턴 종료를 하단 한 줄로 배치하고, 전장과 손패는 그 위의 별도 영역에서 스크롤한다. 버튼 글씨는 16~18px를 유지한다. 세력 선택의 학습·바로 시작·전략·덱 펼치기 버튼도 가로 화면에서 최소 56px 높이를 사용한다.

검증: 별도 테스트 저장으로 회귀 검사 1,356개가 통과했다. 844×390 입력 검사에서 카드 확인·대상 선택·취소·실제 공격과 손패 중앙 스와이프를 확인했다. Android QA 앱에서도 가로 실행·스크롤·세로 전환·가로 복귀를 직접 확인했고, 회전 전후 저장된 전투 스냅샷이 동일했다. 자료는 `build/landscape-buttons-2026-09-14/`에 있다. 실물 휴대폰 검증은 미실시다.

## 가로 전투 재배치

844×390 및 667×375 가로 화면에 적 5칸·아군 5칸·영웅 체력·적 공격 예고·손패를 동시에 표시한다. 전투 전체는 세로 스크롤하지 않고 손패만 좌우로 움직인다. 오른쪽 행동 영역은 폭 144px, 버튼은 최소 높이 52px와 글씨 16px를 사용한다. 긴 이름은 생략 표시하며 전체 이름과 효과는 상세 창에서 확인한다.

손패를 누르면 현재 비용·효과·연계 미리보기와 사용·닫기를 표시한다. 상세 확인 및 배경 연속 탭은 카드를 쓰지 않는다. 사용 시 가능 여부를 다시 검사하며 장비·희생 카드는 대상 확정 전에 자원을 소비하지 않는다. 사용할 수 없는 카드도 설명 확인이 가능하다.

전장 유닛은 400ms 길게 눌러 정보를 확인한다. 12px 이상 움직이면 길게 누르기를 취소하고, 길게 눌렀다가 손을 떼도 공격하지 않는다. Android 뒤로가기는 상세 또는 대상·공격자 선택을 취소한다. 회전 시 미확정 선택은 취소하지만 전투 상태와 저장 형식은 유지한다. 도움 버튼은 설명만 표시한다.

구현: `src/ui/components/landscape_battle_view.gd`가 가로 배치·카드 상세·간단한 카드 표시를 맡고 기존 전투 효과와 대상 선택을 호출한다. 기존 레이아웃에서 공유 정보 패널을 구성한 뒤 표시할 컨트롤을 가로 전용 영역으로 이동한다.

자동 검증: 1,356개 회귀 검사, 세로·데스크톱 입력 검사, 가로 손패 스와이프, 두 가로 해상도의 상세 확인·확정·대상 취소·공격·비용 재검사·길게 누르기·5칸 표시를 확인했다. GUI 종료 시 기존 CanvasItem/ObjectDB 해제 경고는 남아 있다. 실물 휴대폰과 신규 사용자 편의성 평가는 별도다.

추가 검증에서 장비 강화와 시체 폭발의 실제 대상 확정을 확인했다. 상세 창의 확정 버튼은 손패와 좌표가 겹치지 않는 위쪽에 배치해 연속 탭에 의한 사용을 막는다. 화면 자료는 `build/landscape-redesign-2026-09-14/`에 보관한다.

Android QA 앱에서도 상세 열기·뒤로가기로 닫기·카드 사용·장비의 아군 대상 확정·턴 종료를 직접 입력했다. 실제 저장과 분리된 앱에서 실행했으며, 실물 기기 검증으로 간주하지 않는다.

Android에서 공격 가능한 아군을 누른 뒤 적 영웅을 눌러 HP 2→1 감소도 확인했다. 전체 전장과 행동 버튼이 함께 보이는 상태에서 공격을 완료했다.

상세 확인 중 가로→세로→가로 전환 후에도 양쪽 전투 상태가 보존되는 것을 Android QA 저장으로 확인했다.

### 2026-09-15 재검증

가로 전용 카드에 공격 후 체력 예측이 누락된 문제를 수정했다. 공격자를 선택하면 적 카드에 `적3→0 / 내4→4`처럼 양쪽 결과를 표시한다. 기존 전투 계산을 사용하며, 작은 가로 화면 검사에 실제 표시 문구와 계산값의 일치 검사를 추가했다. 긴 전투 제목은 생략 표시해 상단 버튼을 밀지 않게 했다.

Godot 4.6.3 전체 회귀 검사 1,356개와 667×375 가로 입력 검사, 가로 손패 스크롤 검사가 통과했다. 수정 APK를 Android API 36 에뮬레이터의 `com.card_draft.mobileqa`에 설치하고, 별도 저장 경로와 고정 전장으로 터치를 검증했다. 유닛 길게 누르기·뒤로가기, 공격 예측(적 3→0, 아군 4→4)과 실제 처치, 장비 선택 취소 시 자원 보존, 선택한 방패 수호병의 공격력 2→4, 가로→세로→가로 상태 보존, 턴 종료 후 다음 턴 진행을 확인했다.

캡처와 입력 검사 로그는 `build/landscape-verification-2026-09-15/`에 있다. 고정 전장 검사는 전체 런 플레이 검증을 대신하지 않는다. 실물 휴대폰 검증은 미실시이며, 검사 종료 시 기존 CanvasItem/ObjectDB 경고는 남아 있다.

## 가로 전투 카드 표현 개편 (2026-09-15)

위 가로 재배치의 조작 흐름을 유지하면서 표시를 변경했다. 오른쪽 행동 영역은 120px, 버튼 높이는 최소 52px다. 손패는 기본 80×112, 높이 375 이하에서는 76×106이며 8px 간격의 좌우 스크롤을 사용한다. 전장 전체는 세로 스크롤하지 않는다.

카드 그림은 정상 밝기로 표시하고 이름 띠만 어둡게 처리한다. 비용·공격력·체력은 기존 보석 아트를 사용한다. 사용 불가 상태에서는 그림만 어두워지고 비용과 이름은 그대로 읽을 수 있다. 빈 슬롯은 대비를 낮췄고 영웅에는 기존 초상과 체력바를 붙였다. 상세 창에서는 큰 카드 그림과 효과를 함께 보여준다.

공격 대상마다 적·아군의 타격 직후 체력을 표시한다. 적이 한 명일 때는 선택한 아군에도 체력 예측을 표시한다. 여러 적 중 임의의 한 명을 기준으로 아군 체력을 표시하지 않는다. 후속 장비·사망 효과는 예측 범위 밖이다. 선택 취소에는 자원이 소비되지 않는다.

가로 전투의 카드 이동은 180ms, 소환 강조는 180ms, 공격 돌진·복귀는 200ms 이내로 줄였다. 전체 화면 흔들림과 강타의 전체 화면 플래시는 끄고 기존 타격 효과·사운드를 재사용한다. 세로·데스크톱 연출 시간은 유지한다.

게임 규칙과 저장 형식은 변경하지 않는다. 실물 휴대폰의 가독성·미적 만족도는 자동 검사와 별개로 확인해야 한다.

검증 결과: Godot 4.6.3 회귀 검사 1,356개, 667×375·844×390 가로 입력, 390×844 세로 입력, 1280×720 데스크톱 입력, 손패 10장 스크롤 검사가 통과했다. 기존 7장 스크롤 사례는 새 카드 크기에서 한 화면에 들어오므로 실제 넘침이 생기는 10장으로 변경했다. Android API 36 QA 앱에서 상세·사용·취소·길게 누르기·공격·장비 적용을 확인했다. 타격 후 적 처치와 아군 체력 4 유지, 선택한 아군 공격력 2→4를 저장 스냅샷으로 확인했다.

Android 검증 중 전용 카드 그림이 잘못 대체되는 기존 문제를 발견했다. 내보낸 APK의 가져온 텍스처는 원본 파일 존재 검사 대신 `ResourceLoader.exists`로 확인하도록 수정했고, 검과 고블린 초상이 데스크톱과 같게 표시되는 것을 확인했다. 캡처·검사 로그는 `build/tcg-landscape-2026-09-15/`에 있다. 기존 검사 종료 시 CanvasItem/ObjectDB 경고는 남아 있다.

Android 가로→세로→가로 회전 후 양쪽 전투 상태가 동일했고, 턴 종료 후 다음 플레이어 턴(최대 마나 5)으로 진행하는 것도 확인했다. 에뮬레이터 부팅 중 System UI 응답 지연이 한 차례 있었으며, 복구 후 위 입력 검증을 완료했다. 실물 기기와 장시간 성능 검증은 별도다.

### 카드 종류 색과 아이콘

가로 전투의 손패·유닛·상세 카드에는 종류별 고정 테두리와 이름 띠, 오른쪽 위 아이콘을 표시한다. 유닛은 청회색 방패, 피해·저주 주문은 붉은 불꽃, 회복·드로우·소환·강화 등 지원 주문은 녹색 십자, 장비는 금색 검으로 구분한다. 피해와 회복이 섞인 주문은 피해 계열이며, 자해 드로우는 지원 계열이다. 강화 카드도 같은 분류를 유지한다.

사용 가능 여부는 작은 빛 표식과 그림 밝기로, 선택은 별도 흰색 외곽선으로 표시한다. 종류 색은 선택이나 마나에 따라 바뀌지 않는다. 네 아이콘은 프로젝트용 SVG로 직접 작성했다.

종류 표시 적용 후 회귀 검사 1,356개와 667×375·844×390 가로 입력 검사가 통과했다. 혼합 효과·강화 카드의 분류, 종류 테두리·아이콘, 별도 선택선, 카드 확인·취소·공격을 검사했다. 이번 색·아이콘 추가의 화면 검증은 Godot GUI에서 수행했으며 Android 실물 재검증은 하지 않았다. 캡처는 `build/card-types-2026-09-15/`에 있다.
