# 모바일 조작 기준

현재 가로 캔버스의 터치 조작을 설명한다. 화면 배율은 [반응형 UI](ui-responsive.md), 런 진행은 [서비스 흐름도](service-flow.md), 설정값은 [설정](settings.md)을 참고한다.

## 카드와 공격

- 손패를 누르면 카드 전체와 효과를 확인하는 상세 창이 열린다. `사용`을 눌러 진행하며, `닫기`만 하면 카드·마나는 그대로다. 사용할 수 없는 카드도 상세를 볼 수 있다.
- 장비·희생 등 대상이 필요한 행동은 유효한 아군을 선택해야 확정된다. 대상 확정 전 카드·마나·필살기를 소비하지 않는다.
- 공격 가능한 아군을 선택한 뒤 적 유닛 또는 적 영웅을 누른다. 빈 전장 슬롯은 공격 대상이 아니다. 선봉 보호·상대 턴·다른 대상 선택 중에는 영웅을 공격하지 않는다.
- 같은 아군을 다시 누르거나 `선택 취소`를 눌러 공격자 선택을 해제한다. Android 뒤로가기도 상세 창이나 진행 중 선택을 닫는다.
- 유닛을 길게 누르면 상세를 확인한다. 길게 누른 뒤 손을 떼는 동작은 공격으로 처리하지 않는다.
- 세로 손패용 두 번 누르기 코드는 호환 경로로 남아 있지만, 현재 루트는 화면 크기를 가로 캔버스로 정규화한다. 이를 기본 세로 플레이 방식으로 안내하지 않는다.

## 스크롤과 전장 표시

- 카드·버튼 위에서 밀어도 스크롤할 수 있다. 스크롤로 판정한 입력은 손을 뗄 때 카드 사용·공격·버튼 실행으로 이어지지 않는다.
- 적·아군 두 전열과 영웅은 한 화면에 고정 표시한다. 전장을 위아래로 밀어 다른 전열을 찾아갈 필요가 없으며, 손패만 가로로 넘긴다.
- 손패는 비용·이름이 보이도록 접혀 있다. 공격 또는 아군 대상 선택 중에는 더 낮아지고 전장이 넓어지며, 취소·행동 완료 후 원래 높이로 돌아온다.
- 손패·상세 설명을 스크롤해도 행동 버튼과 겹치지 않도록 배치한다. 학습의 `도움 보기`는 조작할 대상을 강조한다.
- 화면 회전·재구성 중에도 확정된 전투 행동은 중복 실행하지 않는다. 미확정 선택과 연출 위치는 영구 게임 상태가 아니다.

이전 스크롤형 전투를 위한 자동 포커스 설정과 연출 취소 처리는 호환 코드로 남아 있다. 상세 창 열기·직접 스크롤·화면 이탈 시 예약된 이동을 취소하지만, 현재 고정 전장에서는 자동 이동 설정으로 두 전열을 번갈아 스크롤하지 않는다.

## 상태 안내

- 사용 가능한 카드와 불가능한 카드를 밝기·테두리·설명으로 구분한다. 색만으로 판단하도록 하지 않는다.
- 아군의 공격 가능·선택됨·소환 대기·공격 완료 상태를 구분하고, 공격할 수 없는 이유를 표시한다.
- 공격 선택 시 양쪽 체력의 예상 변화를 표시한다. 처치 시 반격 생략과 돌파를 반영하지만 후속 사망·장비 효과 전체의 최종 결과를 보장하지 않는다.
- 학습의 `도움 보기`는 가능한 조작 위치를 강조한다. 일반 런의 `전투 정보`는 위협과 공격 결과를 보여준다. 두 기능 모두 카드를 쓰거나 공격·턴 종료를 대신 실행하지 않는다.
- 대상 선택 중에는 턴 종료를 막고 취소를 제공한다. 그 외 내 턴에는 행동이 남아 있어도 직접 종료할 수 있다.
- 시간 제한은 없다. 첫 학습 전투를 제외하고, 행동이 소진되고 선택·상세 보기 등 대기 상태가 없으면 자동으로 턴을 종료한다.

## 배치 원칙

- 전장 카드 크기는 사용 가능 공간에 맞춘다. 모바일 손패는 세로 카드 비율을 유지하고 일부만 노출하며, 상세 창에서는 카드 전체를 보여준다. 논리 크기는 [반응형 UI](ui-responsive.md)를 따른다.
- 긴 설명은 카드 상세에서 확인하고 전장에는 카드 식별 정보·체력·공격 상태를 우선 표시한다.
- 버튼 크기는 공통 [버튼 규격](button-system.md)을 사용한다. 모바일 전투의 안내·정보·취소와 주요 행동 영역을 손패와 분리한다.
- 상점·보상·세력 선택도 주요 확정 버튼을 콘텐츠 스크롤과 분리한다.

## 검증 방법과 한계

모든 실행은 별도 저장 경로를 사용한다. Linux에서 표시 장치가 없으면 렌더링 명령 앞에 `xvfb-run -a`를 붙인다.

```bash
godot --path . -s res://tests/godot/capture_battle_choices.gd -- --test-data-dir=/tmp/card-draft-battle-ui --landscape
godot --path . -s res://tests/godot/capture_battle_choices.gd -- --test-data-dir=/tmp/card-draft-battle-small --landscape --small --race=undead
godot --path . -s res://tests/godot/touch_scroll_test.gd -- --test-data-dir=/tmp/card-draft-touch
godot --path . -s res://tests/godot/enemy_field_touch_test.gd -- --test-data-dir=/tmp/card-draft-enemy-touch
```

사용·공격·취소 시 자원과 공격권, 스크롤 후 오발, 상세 열기·닫기, 고정 버튼 노출을 확인한다. 자동 입력과 모바일 크기 캡처는 실제 손가락 조작감·발열·성능·신규 사용자 이해도 검증을 대신하지 않는다. 전체 실행 안내는 [실행과 테스트](run-and-test.md)에 있다.

## 과거 실기기 근거

[2026-09-22 실물 QA](mobile-qa-2026-09-22.md)와 [성능 측정](phone-performance-2026-09-22.md)은 당시 빌드의 관찰 기록이다. 현재 변경본 전체를 다시 검증했다는 의미는 아니다.

2026-09-23 초보 조작 확인:

실물 SM-G965N의 별도 QA 앱에서 미선택 상대 터치(피해 없음), 소환 대기 안내,
선택 취소(공격권 유지), 선택 후 영웅 피해 40→38, 공격 후 아군 복귀,
다음 턴 공격권·상태 초기화, 적 유닛의 체력 미리보기를 확인했다.
공격 직후 직접 스크롤하면 남은 공격자가 있어도 자동 복귀하지 않는 것도 확인했다.
검증 후 QA 저장 두 파일과 회전 설정을 백업값으로 복원했다.
캡처와 저장 비교 자료는 `build/beginner-controls-2026-09-23/`에 보관한다.
기존 Android 로그의 `can_process: !is_inside_tree()` 오류는 이번 실행에서도 관찰됐다.
공격 중복·진행 정지는 발생하지 않았지만 해당 엔진 로그의 원인은 아직 해결하지 않았다.
