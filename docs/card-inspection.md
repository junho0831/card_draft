# 카드 2.5D 뷰어

전투의 가로 모바일 카드 상세 창과 도감의 ‘크게 보기’에 적용한다. 기존 카드 아트를 재사용하며 전투 손패 자체는 기울이지 않는다.

- 손가락으로 카드를 좌우로 밀거나 마우스를 카드 위에서 움직이면 최대 약 17도 기울어진다.
- 손을 떼거나 포인터가 벗어나면 정면으로 돌아온다. 닫기·사용 버튼은 스크롤 밖에 고정한다.
- 원근 투영, 각도에 따른 빛 반사, 테두리와 그림자를 CanvasItem 셰이더로 표현한다.
- 카드 앞면은 작은 SubViewport에 초기 렌더링한 뒤 캐시한다. 기울기 보간이 끝나면 `_process`도 멈춘다. 3D 모델·센서 권한·외부 음원·신규 아트를 사용하지 않는다.
- 전투 상세와 도감은 큰 카드를 스크롤로 확인한다. 카드 표시 영역은 300×470이며, 화면 높이에 맞춰 축소하지 않는다. 카드 위에서도 세로 드래그는 스크롤, 가로 드래그는 기울이기로 구분한다. 사용·닫기 버튼은 스크롤 밖에 고정한다.

공통 구현은 `src/ui/components/card_inspection_view.gd`, 셰이더는 `src/ui/shaders/card_inspection.gdshader`다. 뷰어는 게임 데이터 대신 이미 만들어진 카드 Control만 받아 카드 사용이나 저장을 실행할 수 없다.

```bash
xvfb-run -a godot --path . -s res://tests/godot/card_inspection_test.gd -- --test-data-dir=/tmp/card-draft-card-inspection
xvfb-run -a godot --path . -s res://tests/godot/capture_battle_redesign.gd -- --test-data-dir=/tmp/card-draft-inspection-input --landscape
```

실행 시 로그의 스크립트/셰이더 오류도 함께 확인한다. 뷰어 테스트는 터치 기울기, 복귀, 정지 상태, 닫기, 플레이어 상태 불변과 세로 도감 배치를 검사하고 PNG를 테스트 저장 경로에 남긴다. 기존 전투 입력 검사는 상세 창 확인 후 사용·취소 흐름을 검증한다. 모바일 실기기 성능과 장시간 발열은 별도 확인 대상이다.

2026-09-15 검증: Godot 4.6.3에서 뷰어 전용 입력·상태 검사가 통과했고, 844×390 전투 입력 회귀도 통과했다. 세로 도감 390×844를 캡처해 카드 이름·그림·설명·닫기 버튼을 확인했다. 자료는 `build/card-inspection-2026-09-15/`에 보관한다. 기존 테스트 종료 시 CanvasItem/ObjectDB 정리 경고는 남아 있다.

Android API 36 QA 앱에서도 터치 드래그 중 기울기 변화와 손을 뗀 뒤 정면 복귀를 캡처했다. 확인 전후 저장된 플레이어 상태가 동일했고 해당 실행 로그에서 스크립트·셰이더 오류는 발견하지 않았다. 패키지 `com.card_draft.mobileqa`의 별도 테스트 저장 경로를 사용했으며 실제 플레이 저장은 사용하지 않았다.

확대 후 뷰어 입력 검사에서 카드 높이 유지, 카드 위 세로 스크롤, 사용 버튼 위치 고정도 확인했다. 확대 화면 자료는 `build/card-inspection-large-2026-09-15/`에 보관한다.
작은 가로 화면 667×375의 기존 전투 입력 검사도 통과했다. Android QA 앱에서 카드 위 세로 드래그로 이름·능력치 영역까지 이동하고 상단 버튼이 고정된 것을 확인했다.

변경 원정 카드 도감에도 같은 뷰어를 사용한다. 가로 화면에서 뷰어를 중앙에 고정하고, 내부 카드 이미지는 카드 레이아웃 크기의 2배로 한 번 렌더링해 고밀도 화면의 글자 흐림을 줄인다. 상세 설명은 세로로 스크롤하며 닫기 버튼은 고정된다.
카드 도감의 SubViewport에서도 게임 테마를 명시적으로 전달해 원래의 한글 글꼴과 굵기를 유지한다.
