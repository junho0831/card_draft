# 실행 조작 점검 기록

2026-09-09 · Godot 4.6.3 · 1280×720 데스크톱, 390×844 모바일

## 발견한 문제와 수정

1. 새 런 시작 버튼의 마우스 입력을 처리하는 중 화면의 노드를 `free()`하여 엔진이 signal 11로 종료됐다. 화면과 모달을 트리에서 분리한 뒤 `queue_free()`로 프레임 끝에 삭제하도록 수정했다.
2. 새 `--test-data-dir` 폴더를 지정해 일반 게임을 실행하면 폴더가 없어서 프로필 저장이 실패했다. 게임 시작 시 폴더를 생성·검증하며 실패하면 종료 코드 2로 중단한다. 개인 저장으로 우회하지 않는다.
3. 일반 진행으로 전환하면 전략이 화면 아래에 나타나고 데스크톱 시작 버튼도 스크롤 밖으로 밀려났다. 전략 영역으로 자동 스크롤하고 시작 버튼을 하단에 고정했다. 화면 전환 후 남은 스크롤 작업은 안전하게 무시한다.
4. 전장의 유닛 그림과 능력치 배지가 입력을 가로채 장비 대상 클릭이 반응하지 않았다. 필드 카드의 장식 노드가 입력을 받지 않도록 하여 카드 버튼으로 전달되게 했다. 아군·적 유닛의 그림, 이름, 능력치 영역에 같은 규칙을 적용한다.

## 실행 확인

데스크톱 조작 도구에서 Godot 창을 찾지 못해, 실행 중인 Godot 창에 마우스 누름·뗌 이벤트를 주입하고 화면을 캡처해 확인했다. 화면의 버튼과 좌표를 선택했으며, 이 확인에서는 전투 효과 함수를 직접 호출해 진행하지 않았다. 전투의 추천 행동 버튼도 사용했다.

인간 정예 선택 → 지도 → 첫 전투 → 유닛 소환·지원 카드 → 턴 전환 → 필살기 → 장비 대상 선택·취소 → 재선택·장착 → 승리 → 카드 보상 확정 → 지도 복귀를 확인했다. 대상 선택 상태에서 재실행한 뒤 저장된 전투가 복원되고 미확정 선택이 취소되는 것도 확인했다. 장비 클릭 수정 후 그림 중앙을 눌러 선택한 유닛의 공격력이 증가하고 카드·마나가 소비됐다.

- 전체 회귀 검증: **1,206개 통과**. 실제 GUI 입력의 화면 전환, 전략 표시·스크롤, 지연 삭제, 유닛 그림 클릭 장비 적용 검사를 포함한다.
- 모바일 전략 선택·덱 펼치기·하단 시작 버튼 캡처 확인.
- 존재하지 않던 중첩 테스트 폴더로 일반 게임을 실행하여 프로필 파일 자동 생성 확인.
- 개인 저장은 사용하지 않았다. 모든 게임과 검증에 별도 `--test-data-dir`를 지정했다.

그래픽 캡처 종료 시 기존 ObjectDB·리소스·텍스처 해제 경고/오류는 남아 있다. 이번 확인은 첫 전투와 보상까지의 조작 검증이며 모든 세력의 전체 런이나 신규 사용자의 재미·완주 시간을 검증한 것은 아니다.
