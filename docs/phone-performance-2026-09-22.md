# Android 실기기 확인 — 2026-09-22

## 조건

- SM-G965N, Android 10, ARM64. `/proc/meminfo`의 총 RAM 약 5.49GiB.
- 화면 설정 2220×1080 가로, USB 충전 중. 별도 debug 앱 `com.card_draft.phoneqa`.
- 작업 중인 세력 선택/전투 초기 스크롤 수정본을 APK로 내보내 설치했다.
- 저장 위치: QA 앱 내부 `files/qa-20260922`. 일반 앱 저장은 사용하지 않았다.
- 실제 ADB 터치·스와이프와 실기기 스크린샷으로 확인했다. 에뮬레이터 결과가 아니다.

## 확인한 동작

- 세력 선택: 첫 화면에서 세 선택 버튼과 시작 버튼을 확인. 엘프 선택 후 학습 런 시작.
- 전투: 새 전투의 적 선봉 카드가 위로 잘리지 않고 전체 표시됨.
- 이어하기, 카드 상세 확인과 사용, 마나 2→1 및 소환, 턴 종료 후 마나 3/3 확인.
- 아군 선택 후 적 영웅을 눌러 체력 7→6으로 감소한 것을 확인.
- 전장 중앙 스와이프로 아군 전열을 볼 수 있고, 행동 대상 자동 이동도 작동함.
- 수집한 두 앱 프로세스 로그에서 SCRIPT ERROR, FATAL EXCEPTION, ANR, out of memory 문구 없음.
- 전체 런, 모든 화면, 장시간 안정성, 실제 FPS는 이번 측정 범위에 포함하지 않았다.

## CPU와 메모리

`adb shell top -b -n N -d 2 -p PID`의 첫 표본을 제외했다.
CPU 100%는 코어 하나를 모두 사용하는 값이다. 8코어 장치 전체는 800%다.
PSS는 공유 메모리를 비례 배분한 앱 메모리이며 `dumpsys meminfo`의 TOTAL PSS를 사용했다.

| 구간 | CPU 표본/기간 | 평균 CPU | 관측 CPU 범위 | 구간 뒤 PSS |
|---|---|---:|---:|---:|
| 메인 메뉴 대기 | 5개 / 약 10초 | 38.9% | 38.5–39.5% | 322.7MiB |
| 전투 대기 | 5개 / 약 10초 | 56.3% | 55.5–57.0% | 331.0MiB |
| 카드 확인·소환·턴 진행 등 조작과 대기 혼합 | 20개 / 약 40초 | 57.0% | 36.5–65.5% | 355.9MiB |
| 홈 화면으로 나간 뒤 | 5개 / 약 10초 | 0.9% | 0–3.5% | 미측정 |

메뉴 복귀 후 PSS는 353.6MiB였다. 시작보다 약 31MiB 높지만, 이 한 차례의 측정으로
캐시 증가인지 누수인지 구분할 수 없다. CPU 표본의 최댓값은 순간 최대 부하를 뜻하지 않는다.
조작 구간 뒤 메모리 측정은 별도 공격 확인 후 수행했으므로 CPU와 완전히 같은 시간 범위는 아니다.

종료 전 배터리 온도는 33.0°C(시작 32.1°C), CPU 센서 38.6°C, Android Thermal Status 0이었다.
USB 충전 중 짧은 테스트이므로 배터리 소모율이나 장시간 발열 성능을 판단하지 않는다.

## 측정 당시 개선 후보

아래 지도·메뉴·카드 상세의 공간 문제는 이후 같은 날 UI 수정으로 개선했다.
실기기 재확인 기록은 `docs/mobile-controls.md`의 2026-09-22 항목을 참고한다.
이 문서의 성능 수치는 그 UI 수정 전 측정값이며, 수정 후 성능은 재측정하지 않았다.

- 전투 대기 CPU가 조작 구간과 비슷하다. 정지 화면의 지속 갱신과 렌더링을 프로파일링하고,
  메뉴/대기 프레임 제한을 검토할 가치가 있다. CPU 병목 위치는 이번에 측정하지 않았다.
- 지도는 안내·진행 표시가 높이를 많이 차지해 경로 확인에 스크롤이 필요하다.
- 카드 상세창과 메인 메뉴 역시 가로 화면에서 세로 공간을 더 효율적으로 쓸 여지가 있다.
- 반복 전투/메뉴 전환 후 메모리 안정화와 release 빌드의 장시간 실행은 별도로 확인해야 한다.
